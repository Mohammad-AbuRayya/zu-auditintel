# ZU-AuditIntel — نظام التدقيق الداخلي للجودة

نظام تدقيق امتثال داخلي لجامعة الزرقاء مبني على متطلبات **ISO 21001:2025**، بواجهة عربية
RTL. يدير بنود التدقيق لكل جهة (المكتبة العامة حالياً)، ويرفع الأدلة المستندية ويفحصها
ثم يصنّف كل بند: مطابق / غير مطابق / يحتاج مراجعة.

> **حالة المشروع: نموذج أولي (Prototype).** الصفحة والبنود والبيانات والدخول حقيقية،
> لكن طبقات الفحص الذكي وحفظ النتائج ولوحات الدورين الآخرين ما تزال تمثيلية وغير صالحة
> للاستخدام الفعلي — موثّقة أدناه بلا تجميل.

## التقنيات

- .NET 10 — Blazor Web App (`InteractiveServer`)، بدون MVC
- EF Core 10 + SQLite
- Bootstrap 5 (مضمّن محلياً في `wwwroot/lib`)

## التشغيل

```bash
dotnet build ZU_AuditIntel.Web
dotnet run --project ZU_AuditIntel.Web        # http://localhost:5124
```

قاعدة البيانات تُنشأ من الترحيلات. أدوات EF مثبّتة محلياً عبر `dotnet-tools.json`:

```bash
dotnet restore
dotnet tool restore
dotnet ef migrations add <Name> --project ZU_AuditIntel.Web
dotnet ef database update --project ZU_AuditIntel.Web
```

ملف `zu_auditintel.db` محلي وغير متتبَّع في git؛ احذفه وأعد `database update` لبنائه من جديد.

## البنية

```
Models/       كيانات الكتالوج: Department, AuditItem, AuditQuestion, AuditEvidenceRequirement + User
Data/         AppDbContext (الإعداد + الزرع)، SeedData (الكتالوج)، AuditCatalog (قراءة)،
              PasswordHasher (PBKDF2-SHA256)، AccountDirectory (الحسابات)
Endpoints/    AccountEndpoints (دخول / تغيير كلمة / خروج + سياسة CanAudit)
AuditClaims.cs ادعاءات المبدأ (الرقم الوظيفي، الجهة، الدور) وتوجيه ما بعد الدخول
Components/   Pages/Login, Pages/ChangePassword, Pages/Pending, Pages/Library_Audit,
              Shared/UserBar
wwwroot/js/   audit-shell.js (زر الخروج عبر POST مضاد للتزييف)
```

**مصدر الحقيقة الوحيد لبنود التدقيق هو `Data/SeedData.cs`.** الواجهات لا تكرّر البنود
محلياً؛ تقرأها عبر `IAuditCatalog` (تسلسل `SortOrder`، وأسئلة وأدلة كل بند في جداوله
الخاصة). أضف بنداً أو عدّله هناك، ثم أنشئ ترحيلاً وطبّقه.

الكيانات تصف *تعريف* البند فقط. نتائج التدقيق (الملفات المرفوعة، حالة الفحص، الدرجة)
تبقى في ذاكرة الجلسة وحدها ولا تُحفظ بعد.

## الهوية والأدوار

الدخول بالرقم الوظيفي عبر كوكيز (`AddAuthentication().AddCookie`)، ومبادئ الترخيص ثلاثة:
`EntityRepresentative` (يملأ قائمة جهة واحدة)، `LiaisonOfficer` (يستقبل ما اجتاز الفحص)،
`QualityHead` (الموافقة النهائية). كلمات المرور مجزّأة بـ PBKDF2-SHA256 على 600 ألف
حالة تكرار مع ملح عشوائي، والمستخدم غير موجود وكلمة المرور الخاطئة يعيدان نفس الرسالة.

الحسابات الأولية تُزرع عند الإقلاع (ليست `HasData` لأن الملح عشوائي) بكلمة مرور أولية
وعلامة تغيير إجباري قبل أي شاشة عمل:

| الرقم الوظيفي | الدور | الجهة | الكلمة الأولية |
|---|---|---|---|
| `1000101` | ممثل الجهة | المكتبة العامة | `Zu#Library1` |
| `1000102` | ممثل الجهة | المركز الصحي | `Zu#Health1` |
| `2000201` | ضابط الارتباط | المكتبة العامة | `Zu#Liaison1` |
| `3000301` | رئيس وحدة الجودة | — | `Zu#Quality1` |

بعد الدخول يوجَّه المستخدم تلقائياً إلى لوحته: ممثل المكتبة إلى `/LibraryAudit`، ومن
لم تُبنَ لوحته إلى `/pending`. صفحة التدقيق محمية بـ `[Authorize(Policy = CanAudit)]`
وتتحقق ثانياً أن جهة المستخدم هي المكتبة قبل تحميل الكتالوج.

نقطة `/signup` ما تزال نموذج تسجيل وهمياً لا يحفظ شيئاً؛ الحسابات تُنشأ من داخل النظام
ولا من التسجيل العام.

## ما هو تمثيلي الآن

| الطبقة | الواقع |
|---|---|
| لوحات الأدوار | `/pending` صفحة انتظار؛ قوائم مراجعة ضابط الارتباط وموافقات رئيس الوحدة غير مبنية. |
| بقية الجهات | كتالوج المكتبة مكتمل؛ بنود سائر الدوائر عناوين بلا أسئلة ولا أدلة في `SeedData`. |
| الفحص الذكي | `RunAiAuditAsync` محاكاة (`Task.Delay`) فوق فحوص regex محلية؛ فحص PDF يقرأ البايتات ولا يستخرج النص، ولا اتصال بـ Ollama بعد. |
| حفظ النتائج | لا يوجد؛ إعادة تحميل الصفحة تصفّر كل الحالات. |
| التعريب | `ar`/`en` مهيّآن في `Program.cs` لكن ملفات `.resx` فارغة والنص العربي مضمّن في المكوّنات. |

الأيقونات تعتمد أصناف `bi bi-*` من Bootstrap Icons، والحزمة غير مثبتة ولا مربوطة في
`App.razor`، فلا تظهر أي أيقونة حتى تُضاف.

## الخطوات التالية

1. حفظ الإرسال ونتائج الفحص: جدول `AuditSubmission` بحالة (مسودة / مقبول أولياً / مرفوض)
   حتى لا يُعاد الفحص عند كل تحميل، وقائمتا المراجعة لضابط الارتباط ورئيس الوحدة.
2. عقود الوكلاء الثلاثة (ضبط الوثيقة والتخطيط، صحة التواقيع والإسناد، التحقق من الأدلة
   ومطابقة المحتوى) ثم المنسّق، على نموذج محلي عبر Ollama خلف `IAuditAgent`.
3. جدول أوزان الملاحظات لحساب نسبة الـ ١٠٪ — الفحوص الثنائية وحدها لا تكفي، فمع أربعة
   فحوص تكون دقة النسبة ٢٥٪ وأي خطأ يرفض الملف.
4. محرك قراءة الوثائق: استخراج نص PDF الحقيقي والتواقيع والأختام بدل فحوص regex.
5. تقرير `ZU/QP02F004` وقائمة `ZU/QP02F003` كمخرجات قابلة للتحميل.
6. توجيه عام `/Audit/{DepartmentId}` بدل صفحة المكتبة الثابتة، وإكمال كتالوج بقية الدوائر.
7. تقسيم `Library_Audit.razor` (1180 سطراً) إلى مكوّنات، وتعبئة `.resx`، وربط Bootstrap Icons.
8. قفل الحساب بعد تكرار الفشل (التقييد الحالي ١٠ محاولات في الدقيقة بدون قفل) وحذف
   `/signup` الوهمي.
